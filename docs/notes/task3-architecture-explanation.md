# Task 3 框架特征注入 —— 理清数据流与设计动机

> 配合 `docs/plans/phase3.2-task3-architecture-enhancement.md` 阅读。本文是对 Phase 3.2 增强方案的概念性解释，回答三个问题：
> 1. 当前 Task3 为什么做得不好？
> 2. 增强架构每一步在做什么、数据从哪里来？
> 3. 为什么这么设计就够了？

---

## 一、当前 Task 3 的信息缺口

### 1.1 致命缺陷

当前 `model_task3.py` 与 `model_task1.py` **结构完全相同**：

```
句子 + 目标词标记[1][2] → BERT(最后4层平均) → Dense → GlobalPointer(Q,K) → 取 span 位置分数 → CrossEntropy → 角色分类
```

**它不知道当前目标词激活了哪个框架。** 模型面对一个论元 span（如"张三"），必须从全局角色标签池中做分类，而无法利用"当前激活了'商业购买'框架，候选角色只有买方/商品/卖方..."这一信息。

### 1.2 实测验证

**训练代码** — `dataset_task3.py` 完全没有读取 `frame` 字段：

```python
# dataset_task3.py:26-43 — 没有任何 "frame" 相关代码
for line in self.all_data:
    text = line["text"]
    target = [...]
    cfn_spans = line["cfn_spans"]
    for spans in cfn_spans:
        self.data.append({
            "label_class": self.label2idx[spans["fe_name"]],  # 只用 fe_name
            "label_idx": [start, end],                        # span 边界
            # ← 没有 frame_name！训练数据里的 "frame" 字段被直接忽略了
        })
```

`frame_info.json` 只在构建标签词表时被用到——遍历所有框架的所有 FE，把唯一 `fe_name` 收集成平铺列表，框架与角色的从属关系**全部丢失**。

**实测数据：**

| 指标 | 数值 |
|------|:---:|
| 框架种类数 | 713 |
| **Task3 标签空间** | **1009 个唯一 FE 名称** |
| 每框架平均 FE 数 | 42.7 |
| 总 FE 条目（含重复）| 30,472 |

模型面对一个论元 span，要从 **1009 个候选角色**中选一个。它不知道当前是"举报"（候选：告发者/官方/作恶者/行为...）还是"商业购买"（买方/商品/价格/卖方...）。

### 1.3 基线实验证据

| 实验 | Task3 F1 (A榜) | 说明 |
|------|:-----------:|------|
| E3 (BERT-wwm baseline) | 58.23 | 无框架信息 |
| E5 (RoBERTa-wwm) | 58.40 | 仅换模型，+0.17 |

Task3 在 RoBERTa 升级后几乎原地踏步（+0.17），远小于 Task1（+1.21）和 Task2（+0.48）。更强的文本编码器对分类的边际收益已经很小，瓶颈在于架构本身缺少框架信号。

## 二、当前架构的完整数据流

以具体句子为例，跟踪模型实际看到的信息流：

```
输入: "张三代人购买了一台电脑"
目标词: 购买 → 插入标记后 → [1]购买[2]
论元span: "张三" [0, 2) → 要判断它是什么角色

                    [CLS] 张 三 代 人 [1] 购 买 [2] 一 台 电 脑 [SEP]
                              │
                     BERT 12层编码
                              │
                取最后4层平均 → hidden_token (batch, seq_len, 768)
                              │
              Dense(768 → 1009×64×2)    ← 1009 = 所有唯一角色名
                              │
                     拆成 Q 和 K，加 RoPE 位置编码
                              │
           einsum('bmhd,bnhd->bhmn', Q, K) → 得分矩阵
           shape: (batch, 1009, seq_len, seq_len)
                              │
          取位置 [span_start, span_end] → token_logits
           shape: (batch, 1009)
                              │
                    argmax → 从 1009 个角色里盲选一个
```

**模型实际看到的信息：**
- ✅ 句子的字面内容
- ✅ 目标词是"购买"（通过 [1][2] 标记）
- ✅ 论元的字符边界
- ❌ **这句话激活的是什么框架？——完全不知道**

**具体为什么出错：**

```
角色                 分数    来源
────────────────────────────────────
买方(商业购买)       3.2    ← "张三"是人名，训练数据中人名→买方的频率高
告发者(举报)         2.8    ← 没有上下文告诉它"这不是举报场景"
官方(举报)           1.1
商品(商业购买)       0.5
作恶者(举报)        -0.3
...                  ...
(还有 ~1003 个)      ...    ← 大量无关标签也在竞争
────────────────────────────────────
→ argmax = "买方" ❌ 错了
```

模型只能依赖"张三是一个人名"这类表层特征，无法利用"目标词激活了商业购买框架，候选角色只有买方/商品/价格..."这一关键约束。

## 三、增强架构的数据流

**核心思路**：不推翻 GlobalPointer，只在其输出上叠加一个框架偏置信号。

```
          ┌─────────────────────────────────┐
          │  Path 1: 和原来完全一样           │
          │  BERT → 4层平均 → Dense         │
          │  → Q,K + RoPE → GlobalPointer   │
          │  → token_logits (batch, 1009)   │
          └──────────────┬──────────────────┘
                         │
          ┌──────────────┼──────────────────┐
          │  Path 2: 框架偏置（新增）          │
          │                                  │
          │  frame_name = "商业购买"           │
          │      ↓                            │
          │  FrameEmbedding(713 → 256)        │  ← 每个框架一个可学习向量
          │      ↓                            │
          │  frame_vec (256,)                 │
          │      ↓                            │
          │  Linear(256 → 1009)               │  ← 从框架特征映射到角色偏置
          │      ↓                            │
          │  frame_bias (1009,)               │
          │                                  │
          └──────────────┬──────────────────┘
                         │
                 两者逐元素相加
                         │
        final_logits = token_logits + frame_bias
        shape: (batch, 1009)
                         │
                  argmax → 角色预测
```

**加上偏置后，同样的例子发生了什么：**

```
角色              原始分数    框架偏置    最终分数
─────────────────────────────────────────────────
买方(商业购买)       3.2      +5.1       8.3   ← 框架说：商业购买下买方最常见
商品(商业购买)       0.5      +4.8       5.3   ← 框架抬高了本场景相关的角色
告发者(举报)         2.8      -6.2      -3.4   ← 框架说：不存在于商业购买，压死
官方(举报)           1.1      -5.9      -4.8   ← 同样被压死
作恶者(举报)        -0.3      -5.5      -5.8
...                  ...      ...       ...
─────────────────────────────────────────────────
→ argmax = "买方" ✅ 正确
```

`frame_bias` 向量本质上就是框架嵌入从训练中学到的知识：**"在这个框架下，哪些角色值得加分，哪些该直接压到负分"**。

## 四、Path 2 每个数据流的来源详解

Path 2 中的每一步是**从哪里来的**——这一点很容易混淆。

```
Path 2: frame_name → frame_id → FrameEmbedding → frame_vec → Linear → frame_bias
```

### ① `frame_name`（字符串，如 "商业购买"）

| 问题 | 答案 |
|------|------|
| 训练时从哪来？| **训练数据 `cfn-train.json` 里的 `"frame"` 字段**。原代码读了这个文件但跳过了 `frame`，Phase 3.2 把它捡起来用 |
| 预测时从哪来？| **Task 1 模型的预测输出**（`B_task1_test.json`），不是 gold truth |
| 是 RoBERTa 给的吗？| **不是**。训练时是数据标注给的，预测时是 Task 1 模型输出的 |

### ② `frame_id`（整数，如 156）

| 问题 | 答案 |
|------|------|
| 从哪来？| **人工构建的映射表**。遍历 `frame_info.json`，按顺序给每个 `frame_name` 分配一个数字 ID |
| 怎么保证一致性？| 训练和预测时用完全相同的方式构建（都遍历同一个 `frame_info.json`），保证"商业购买"始终映射到同一个数字 |
| 是 RoBERTa 给的吗？| **不是**。就是一个 Python 字典：`{"辨别": 0, "举报": 1, "商业购买": 156, ...}` |

### ③ `FrameEmbedding(713, 256)`

| 问题 | 答案 |
|------|------|
| 从哪来？| **完全随机初始化，通过 Task 3 训练学习**。`nn.Embedding(713, 256)` 一开始是随机数，随着 loss 反向传播逐步更新 |
| 是 RoBERTa 给的 embedding 吗？| **绝对不是**。RoBERTa 只在 Path 1 里把汉字变成 768 维向量。这里的 FrameEmbedding 是给 713 个框架各学一个 256 维向量 |
| 类比 | RoBERTa 把"字"编码成向量；FrameEmbedding 把"框架名"编码成向量。后者是全新的、从零开始学的 |

### ④ `frame_vec`（向量，256 维）

```python
frame_vec = self.frame_embedding(torch.tensor([156]))
# 等价于查表：从 713×256 的矩阵里取出第 156 行
```

就是 FrameEmbedding 做了一次查表操作。输入框架 ID，输出该框架对应的 256 维向量。

### ⑤ `Linear(256, 1009)` + `frame_bias`（向量，1009 维）

| 问题 | 答案 |
|------|------|
| 从哪来？| **完全随机初始化，通过 Task 3 训练学习**。`nn.Linear(256, 1009)` 一开始是随机权重，随着训练更新 |
| 做了什么？| 把框架的 256 维特征向量投影到 1009 维的角色空间。每个维度对应一个角色，数值越大表示"这个框架下，这个角色越常见" |
| 是 RoBERTa 给的？| **不是** |

## 五、一张图：两条 Path 的来源对比

```
Path 1 (来自 RoBERTa):                    Path 2 (完全从零学习):

句子 ──→ RoBERTa ──→ hidden_states         frame_name ──→ 查表 ──→ frame_id
            │                                                    │
       预训练权重                                              手动映射
      (chinese-roberta-wwm-ext)                             (frame_info.json)
            │                                                    │
            ↓                                                    ↓
      Dense(768→1009×128)                              FrameEmbedding(713→256)
            │                                                    │
       随机初始化                                             随机初始化
       (训练中学习)                                            (训练中学习)
            │                                                    │
            ↓                                                    ↓
      Q, K + RoPE                                           frame_vec
            │                                                    │
            ↓                                                    ↓
      GlobalPointer                                        Linear(256→1009)
      → token_logits                                             │
            │                                               随机初始化
            │                                               (训练中学习)
            │                                                    │
            └────────────────┬───────────────────────────────────┘
                             │
                    两者相加: token_logits + frame_bias
                             │
                        → final_logits
                             │
                        → argmax → 角色
```

**总结：Path 2 的 FrameEmbedding 和 Linear 都是全新的、随机初始化的参数，和 RoBERTa 预训练权重没有任何关系。它们通过 Task 3 的 CrossEntropyLoss 反向传播，从头学习"每个框架偏爱哪些角色"这一知识。**

## 六、为什么只加偏置就够了？（而非大改架构）

| 理由 | 说明 |
|------|------|
| **搜索空间硬约束** | 同一 `fe_name` 不会出现在所有 713 个框架中。很多角色是框架专属的（"告发者"→举报，"买方"→商业购买），框架信息 ≈ 硬排除 |
| **保留 GlobalPointer 能力** | GlobalPointer 已经学到了 span 的边界-角色关联（长 span 倾向于"行为"类角色，短 span 倾向于"实体"类角色），这部分不应该破坏 |
| **最小参数量** | FrameEmbedding(713×256) + Linear(256×1009) ≈ 44 万参数，仅占 BERT(1.02 亿) 的 0.4%，不会过拟合 |
| **可解释性** | 训练完成后可以直接查看每个框架的 `frame_bias`，看它学到了哪些角色偏好 |
