# 数据增强为什么能提升性能？

> 配合 `docs/plans/phase3.3-data-augmentation.md` 阅读。

---

## 一、模型目前是怎么"偷懒"的

以 Task 1（框架识别）为例，模型要判断"购买"激活的是"商业购买"框架。训练集可能长这样：

```
"他在网上购买了一本书"      → 商业购买
"我在商店购买了一件衣服"    → 商业购买
"她昨天购买了三斤苹果"      → 商业购买
```

**模型可能学到的不是"购买 → 商业购买"的语义映射，而是训练数据的表面特征：**

- "购买前面两个字经常是'上''店''天'"
- "句子长度通常 10-12 个字"
- "句子中没有任何标点符号"

这不是理解，是**过拟合到了训练集的表观统计特征**。

测试集一旦出现不同的表面模式：

```
"他在网上，购买了一本书。"   ← 多了逗号
"通过平台购买，共计三件。"   ← 结构不同
```

模型就会犹豫——它记住的那些"规律"不管用了。

## 二、AEDA 如何逼模型学真东西

AEDA 每次插入 2-3 个随机标点。同一个句子变成多种表面形式：

```
原始:   张三代人购买了一台电脑
增强1:  张三代人，购买了一台。电脑
增强2:  张三；代人购买了一台电脑，
增强3:  张三代人购买，了一台。电脑？
```

**关键：frame 不变、论元边界不变、角色标签不变。**

模型被强制面对一个事实：无论标点插在哪，答案都一样。它不能再靠"第 5 个字符是购、第 6 个是买"这种位置记忆来答题，必须去学更底层的语义信息——这个动词是什么含义、周围出现了什么类型的实体。

**类比**：考试前不仅做原题，还做了一堆故意加了干扰符号的变体题。到了考场，原题也能做，带干扰的也能做。

### AEDA 的一个关键细节：不能拆开论元

随机插入不是真正随心所欲地"随机"。如果标点恰好插在一个论元内部，会把它拆成两段：

```
原文: "张三代人购买了一台电脑"
论元:  [张三]                     ← "张三"是一个论元

如果标点插在"张"和"三"之间:
  "张，三代人购买了一台电脑"       ← "张三"被拆开了！
  
标注中的论元 [0, 2) 不再对应"张三"，标注被破坏了。
```

**解决方案**：插入位置必须排除"禁区"——目标词内部和所有论元内部：

```
原文: "张三代人购买了一台电脑"
论元:  [张三][代人]      [一台电脑]
目标词:             [购买]

禁区（不可插入）:
  目标词内部: "购"和"买"之间         ✗
  论元内部:   "张"和"三"之间         ✗
              "代"和"人"之间         ✗
              "一""台""电""脑"之间   ✗

安全位置（可以插入）:
  "张三" 和 "代人" 之间              ✓
  "代人" 和 "购买" 之间              ✓
  "购买" 和 "一台电脑" 之间          ✓
  "一台电脑" 之后                    ✓
```

插入位置只落在**论元之间的空隙**里，不进入任何论元内部。这样：
- 论元的内部结构完整——"张三"不会被拆成"张，三"
- 论元边界连续——坐标偏移是整数级的，边界保持不变
- 标点只出现在语义单元之间——这恰好是真实文本中标点的出现规律

**这个约束不是在限制增强，而是让增强结果更接近真实文本。**

## 四、同义词替换

### 原理

将句子中非关键的词替换为同义词，保持句子语义不变但改变字面形式：

```
原始:  "张三代人购买了一台电脑"
替换:  "张三代人购置了一台电脑"     ← "购买" → "购置"
```

### 为什么能起作用

AEDA 是**纯噪声注入**——标点本身不携带语义，只是干扰。同义词替换则不同：它改变的是**有实际含义**的词。

| 增强类型 | 改变什么 | 模型学到什么 |
|------|------|------|
| AEDA | 表面形式 | 忽略标点干扰，抓住核心词 |
| 同义词替换 | 词语选择 | "购置"和"购买"激活同一个框架，不被特定措辞误导 |

对于框架识别（Task 1），这一点尤其有用——"购买""购置""采购""置办"激活的都是"商业购买"框架。如果训练集只有"购买"，测试集出现"购置"，模型就容易出错。同义词替换可以弥补这种词表覆盖缺口。

### 为什么不用

**两个致命问题：**

**1. 中文同义词表质量不可控。** 没有成熟的、可直接使用的中文同义词库。如果用 word2vec 相似度来找"同义词"，会出现大量伪同义：

```
"购买" 的 top-3 相似词（word2vec）可能是:
  "销售" — 反义词！语义完全不兼容
  "购入" — 可以
  "卖出" — 反义词！
```

一旦替换错了，标签就跟着错了。对分类任务来说，把"购买"换成"销售"，frame 还是"商业购买"吗？对论元角色来说，"张三代人销售了一台电脑"中"张三"不是买方而是卖方。**一个错误的替换会污染标注。**

**2. 需要维护排除名单。** 目标词不能换（它是输入），论元范围内的词不能换（它们是标签）。每次替换需要精确判断每个词是否在敏感区域内，实现复杂度远高于 AEDA。

## 五、回译（Back Translation）

### 原理

将句子翻译成另一种语言，再翻译回来。中间语言的差异性会自然改写句子：

```
原始:      "张三代人购买了一台电脑"
翻译成英文: "Zhang San bought a computer on behalf of someone"
翻译回中文: "张三替人购买了一台计算机"

原始 frame:  商业购买
新句 frame:  商业购买  ← 不变
```

### 为什么能起作用

回译是三种方法中**最自然的**增强方式。它不插入无关符号（AEDA），不依赖脆弱的同义词表（同义词替换），而是让翻译模型内部的 paraphrase 能力产生真正多样化的表达：

- "代人购买" → "替人购买" → "帮别人买"
- "一台电脑" → "一台计算机" → "一部电脑"
- 语序可能改变、用词可能改变，但**语义框架不变**

这种多样性覆盖了 AEDA 和同义词替换都做不到的维度——**句法结构变化**。AEDA 只是加标点，同义词替换只是换词，而回译可以改变语序、拆分/合并短语、使用不同的句式。

### 为什么不用

**两个现实问题：**

**1. 翻译模型的不可控性。** 翻译模型可能：
- 丢失关键信息："张三代人购买了一台电脑" → "张三买了东西"（丢失了"代人""一台电脑"）
- 引入幻觉："张三购买了一台电脑" → "张三在京东买了一台联想电脑"（多出了"京东""联想"）
- 改变语义角色：翻译中主语/宾语关系有时会被反转

这些情况下，论元边界和角色标签可能不再匹配。需要用规则或人工检查来过滤，工作量远超 AEDA。

**2. 时间成本不匹配。** 回译需要调用翻译 API（如 Google Translate、DeepL）或本地运行翻译模型。以 ~10700 条训练数据计，每条翻译两次（中→英→中），即使批量调用也要数小时。而截止日期是 **8 月 1 日 12:00**，剩下不到 4 天，还有其他改进项要完成。

## 六、三种方法对比总结

| 维度 | AEDA | 同义词替换 | 回译 |
|------|:--:|:--:|:--:|
| 实现复杂度 | 极低（20 行代码） | 中（需要同义词表） | 高（依赖翻译 API） |
| 标注安全 | 高（标点不影响标签） | 低（换错词=标错签） | 中（翻译不可控） |
| 增强多样性 | 低（只加噪声） | 中（词级变化） | 高（句法+词级变化） |
| 对 span 任务友好 | 中（坐标需修正） | 低（替换影响边界对齐） | 低（翻译改变句子长度和结构） |
| 耗时 | < 1 秒 | 需准备资源 | 数小时 |
| Phase 3.3 选择 | ✅ 采用 | ❌ 风险太高 | ❌ 时间不够 |

---

## 七、一句话

> AEDA 不教模型新知识，而是**移除模型可以作弊的捷径**，迫使它用真正有效的语义特征来答题。
