# CFSP 任务详解

## 一、大背景：这个任务在做什么？

### 直观理解

给你一句中文句子和一个**目标词**（通常是动词），你要回答三个问题：

> 例句：「张三代人购买了一台电脑。」

以「**购买**」为目标词：

**问题 1（框架识别）**：「购买」这个词激活了什么语义框架？
→ 答案是 **「商业购买」**

**问题 2（论元范围识别）**：「商业购买」这个场景涉及哪些角色，它们对应句子中哪些片段？
→ 「张三」是一个论元（买方），覆盖 `[0, 2)` 这个字符区间
→ 「代人」是一个论元（中介），覆盖 `[2, 4)` 这个区间
→ 「一台电脑」是一个论元（商品），覆盖 `[5, 9)` 这个区间

**问题 3（论元角色识别）**：这些片段分别扮演什么角色？
→ `[0, 2)` 张三 → **买方**
→ `[2, 4)` 代人 → **中介**
→ `[5, 9)` 一台电脑 → **商品**

### 用一张图串起来

```
输入: 句子 + 目标词
        ↓
  [Task 1] 目标词激活哪个框架？ → "商业购买"
        ↓
  [Task 2] 框架中哪些片段是论元？ → 张三[0,2)、代人[2,4)、电脑[5,9)
        ↓
  [Task 3] 每个论元是什么角色？ → 买方、中介、商品
```

**这三个任务是层层递进的**：先知道是什么场景，再知道哪些人在参与，最后知道每个人扮演什么角色。

## 二、核心概念解释

### 2.1 什么是「框架（Frame）」？

框架是描述**一类事件或场景**的认知结构。每个框架定义了：

- 这个场景有哪些**参与者**
- 每个参与者的**角色**

例如「举报」框架：

```
[告发者] 向 [官方] 揭发 [作恶者] 的 [行为]

角色列表见 frame_info.json:
  告发者 (inf, Informer)    — 谁举报
  官方 (auth, Authorities)   — 举报给谁
  作恶者 (wd, Wrongdoer)     — 举报谁
  行为 (beh, Behavior)       — 举报什么事
  方式 (manr, Manner)        — 怎么举报
  处所 (place, Place)        — 在哪举报
  目的 (purp, Purpose)       — 为什么举报
  时间 (time, Time)          — 什么时候举报
```

**关键点**：同一个句子可以有多个目标词，每个目标词激活不同的框架。所以**目标词是必须的输入**——它告诉模型「你要分析的是哪个词」。

### 2.2 什么是「论元（Argument）」？

论元是**框架场景中的参与者**在句子中的具体体现——它是在句子中出现的某个片段（一个连续的字符区间）。

**论元 ≠ 每个角色都出现**：一个句子不一定包含框架定义的所有角色。比如「举报」框架有 8 个角色，但实际句子可能只出现 3-5 个。

### 2.3 什么是「目标词（Target）」？

目标词是**激活框架的核心词**，通常是句子的谓语动词。

它的角色类似于：
>「揭发」这个词之所以能被理解，是因为我们脑海中存在一个「举报」场景（有告发者、作恶者、官方……）。「揭发」就是这个场景的入口。

## 三、数据集详解

### 3.1 数据文件一览

| 文件 | 内容 | 大小 |
|------|------|------|
| `cfn-train.json` | 训练集（有标注） | ~42 MB |
| `cfn-dev.json` | 验证集（有标注） | ~9.4 MB |
| `cfn-test-A.json` | A 榜测试集（无标注） | ~9.6 MB |
| `cfn-test-B.json` | B 榜测试集（无标注） | 赛前开放 |
| `frame_info.json` | 所有框架的定义和角色列表 | ~8.6 MB |

### 3.2 训练/验证数据格式

```json
{
  "sentence_id": 2611,
  "text": "当地群众纷纷起来联名向官府揭发刘方济利用传教为非作歹的丑恶罪行。",
  "frame": "举报",
  "target": [
    { "start": 13, "end": 14, "pos": "v" }
  ],
  "cfn_spans": [
    { "start": 0,  "end": 2,  "fe_abbr": "inf",  "fe_name": "告发者" },
    { "start": 8,  "end": 8,  "fe_abbr": "manr", "fe_name": "方式"   },
    { "start": 10, "end": 11, "fe_abbr": "auth", "fe_name": "官方"   },
    { "start": 15, "end": 16, "fe_abbr": "wd",   "fe_name": "作恶者"  },
    { "start": 15, "end": 29, "fe_abbr": "beh",  "fe_name": "行为"   }
  ],
  "word": [
    { "start": 0,  "end": 1,  "pos": "nl" },
    { "start": 2,  "end": 3,  "pos": "n"  },
    { "start": 4,  "end": 5,  "pos": "d"  },
    { "start": 6,  "end": 7,  "pos": "v"  },
    { "start": 8,  "end": 9,  "pos": "v"  },
    { "start": 10, "end": 10, "pos": "p"  },
    { "start": 11, "end": 12, "pos": "n"  },
    { "start": 13, "end": 14, "pos": "v"  },
    { "start": 15, "end": 17, "pos": "nh" },
    { "start": 18, "end": 19, "pos": "v"  },
    { "start": 20, "end": 25, "pos": "v"  },
    { "start": 26, "end": 26, "pos": "u"  },
    { "start": 27, "end": 28, "pos": "a"  },
    { "start": 29, "end": 30, "pos": "n"  },
    { "start": 31, "end": 31, "pos": "wp" }
  ]
}
```

#### 字段逐一解释

**`sentence_id`**：句子的唯一编号。训练集中每条数据一个 ID，提交结果时需要带上这个 ID。

**`text`**：原始的中文句子文本。

**`target`**：目标词信息。
- `start` / `end`：目标词在 `text` 中的**字符位置**（注意是字符索引，不是 token 索引）
- 这两个索引是**闭区间**：`[start, end]`，即 start 到 end 都包含
- `pos`：词性，`v`=动词，`n`=名词等
- 注意 `target` 是一个数组，但通常只有一个元素。取最后一个元素 `target[-1]`

**`frame`**：该目标词激活的框架名。数据集中大约有几百种不同的框架。

> 关于 `frame` 的更多信息在 `frame_info.json` 中，包括框架定义、包含哪些角色、每个角色的缩写等。

**`cfn_spans`**：已标注的论元列表（**这是训练时的标签**）。
- `start` / `end`：论元在句子中的字符位置（闭区间）
- `fe_abbr`：框架元素缩写（如 `inf` = Informer）
- `fe_name`：框架元素的中文名称（如「告发者」）

**重要：论元可以有重叠**

在这个例子中：
- `[15, 16]` → 「刘方济」是**作恶者**
- `[15, 29]` → 「刘方济利用传教为非作歹的丑恶罪行」是**行为**

两个论元共享起始位置 15，一个短一个长。模型需要能同时预测这两个不同的论元。

**`word`**：句子中每个词的分词结果。
- 每个词有 `start`、`end`（字符区间）和 `pos`（词性）
- 注意 `cfn_spans` 和 `target` 的边界**不一定**与分词边界对齐
- `word` 字段提供的是额外的语言学信息，baseline 中实际**并未使用**

### 3.3 测试数据格式

测试数据（`cfn-test-A.json` / `cfn-test-B.json`）的格式与训练数据**基本一致，但不包含**：
- `frame` 字段
- `cfn_spans` 字段

模型需要自己预测这两个字段。

测试数据的 `target` 字段仍然给出（因为目标词是输入的一部分）。

### 3.4 框架信息（frame_info.json）

定义了所有可能的框架及其包含的角色：

```json
{
  "frame_name": "举报",
  "frame_ename": "Reporting",
  "frame_def": "告发者向当局揭发作恶者的不法或不当行为。",
  "fes": [
    { "fe_name": "告发者", "fe_abbr": "inf",  "fe_ename": "Informer",    "fe_def": "向当局告发的人" },
    { "fe_name": "方式",   "fe_abbr": "manr", "fe_ename": "Manner",       "fe_def": "举报的方式" },
    { "fe_name": "官方",   "fe_abbr": "auth", "fe_ename": "Authorities",  "fe_def": "处理不良行为的官员/机构" },
    { "fe_name": "作恶者", "fe_abbr": "wd",   "fe_ename": "Wrongdoer",    "fe_def": "被举报的人" },
    { "fe_name": "行为",   "fe_abbr": "beh",  "fe_ename": "Behavior",     "fe_def": "被举报的行为" },
    { "fe_name": "处所",   "fe_abbr": "place","fe_ename": "Place",        "fe_def": "举报发生的场所" },
    { "fe_name": "目的",   "fe_abbr": "purp", "fe_ename": "Purpose",      "fe_def": "告发者的意图" },
    { "fe_name": "时间",   "fe_abbr": "time", "fe_ename": "Time",         "fe_def": "告发的时间" }
  ]
}
```

**用途**：
- Task 1：框架标签空间由 `frame_info.json` 中所有 `frame_name` 组成（几百类）
- Task 3：角色标签空间是框架相关的——知道是「举报」框架后，候选角色就是上面 8 个

## 四、三个子任务详解

### 子任务 1：框架识别（Frame Identification）

| 项目 | 说明 |
|------|------|
| **做什么** | 给定句子 + 目标词 → 判断目标词激活了哪个框架 |
| **本质** | 多分类问题，标签数 = 框架种类数（几百类） |
| **输入** | 句子文本 + 目标词位置 |
| **输出** | `[sentence_id, "框架名称"]` |
| **评测** | **准确率（Accuracy）**：预测正确的个数 / 总个数 |
| **权重** | 0.3 |

**输出格式示例**：
```json
[
  [2611, "举报"],
  [2612, "等同"],
  [2613, "商业购买"]
]
```

### 子任务 2：论元范围识别（Argument Identification）

| 项目 | 说明 |
|------|------|
| **做什么** | 给定句子 + 目标词 → 找出所有论元的边界范围 |
| **本质** | Span 检测问题（类似 NER，但论元可以重叠） |
| **输入** | 句子文本 + 目标词位置 |
| **输出** | `[sentence_id, span_start, span_end]` 列表 |
| **评测** | **P / R / F1**（基于 token 级别的重叠计算） |
| **权重** | 0.3 |

**评测公式**：
```
precision = 预测论元覆盖的 token 数 ∩ 真实论元覆盖的 token 数 / 预测论元覆盖的总 token 数
recall    = 预测论元覆盖的 token 数 ∩ 真实论元覆盖的 token 数 / 真实论元覆盖的总 token 数
F1        = 2 × precision × recall / (precision + recall)
```

**输出格式示例**：
```json
[
  [2611, 0, 2],
  [2611, 8, 8],
  [2611, 10, 11],
  [2611, 15, 16],
  [2611, 15, 29],
  [2612, 5, 7]
]
```

> 同一个 sentence_id 出现多次 = 该句有多个论元。注意索引是**闭区间**，即 span 的起止索引都包含。

### 子任务 3：论元角色识别（Role Identification）

| 项目 | 说明 |
|------|------|
| **做什么** | 给定句子 + 目标词 + 框架 + 论元范围 → 判断每个论元的角色 |
| **本质** | Span 级别的关系分类 |
| **输入** | 句子文本 + 目标词位置 + 框架信息 + 论元范围 |
| **输出** | `[sentence_id, span_start, span_end, "角色名称"]` |
| **评测** | **P / R / F1**（基于完全匹配的计数） |
| **权重** | 0.4 |

**评测公式**：
```
precision = 正确预测的论元角色个数 / 预测的论元总个数
recall    = 正确预测的论元角色个数 / 真实的论元总个数
F1        = 2 × precision × recall / (precision + recall)
```

> 注意：这里的 F1 计算方式与 Task 2 不同。Task 2 是按 **token 重叠**算的（部分匹配也算分），Task 3 则是按**整条论元**算的（span + 角色标签都要完全一致才算对）。

**输出格式示例**：
```json
[
  [2611, 0, 2, "告发者"],
  [2611, 8, 8, "方式"],
  [2611, 10, 11, "官方"],
  [2611, 15, 16, "作恶者"],
  [2611, 15, 29, "行为"],
  [2612, 5, 7, "时间"]
]
```

## 五、提交要求

### 文件结构

```
submit.zip
├── A_task1_test.json    ← Task 1 预测结果
├── A_task2_test.json    ← Task 2 预测结果
└── A_task3_test.json    ← Task 3 预测结果
```

### 压缩命令

```bash
zip submit.zip A_task1_test.json A_task2_test.json A_task3_test.json
```

> ⚠️ 解压后不能有中间目录，三个文件必须在 zip 的根目录。

### 提交限制

- A 榜：每天最多 **5 次**
- B 榜：每天最多 **5 次**
- 每个任务可以单独提交（未提交的任务按 0 分算）

## 六、评分公式

```
总分 = 0.3 × Task1准确率 + 0.3 × Task2_F1 + 0.4 × Task3_F1
```

全部采用**百分制**，保留两位小数。

由公式可以看出：
- **Task 3 权重最高（0.4），且 baseline 最低（57.08），是提升空间最大的任务**
- Task 1 是上游任务——框架识别错了，Task 3 的输入就有问题，连锁影响
- Task 2 的 baseline 最高（83.06），提升难度最大

## 八、一句总结

> **输入**：中文句子 + 目标词位置  
> **输出**：框架标签 + 论元边界列表 + 每个论元的角色标签  
> **方法**：BERT 系预训练模型微调  
> **重点**：Task 3 权重最高、baseline 最低，是主攻方向
